작업일: 2026-08-06 / 대상: `app/api.py::vectorize`, `src/vector/*`, `app/ppt/_vtrace_run.py`, `app/ui/*`

## 1. 무엇이 문제였나 (재현·확인 완료)

Gemini가 만들어 둔 `src/vector/vector_autotune.py`는 **docstring만 있고 실제 알고리즘은 없는 껍데기**였다.
"다중 파라미터 SSIM 평가 및 최적 SVG 생성"이라고 적혀 있었지만 후보 탐색 루프가 없었고,
`compute_ssim()`은 **무조건 `0.88`을 반환하는 상수 함수**였다(UI에 "SSIM 88%"로 표시되던 그 숫자).

글자가 깨진 실제 원인 4가지 — 모두 재현해서 확인했다.

| # | 원인 | 위치(옛 코드) | 결과 |
|---|---|---|---|
| 1 | **`filter_speckle` 강제 상향** — 전처리 후 색 수가 6000을 넘으면 무조건 `10`으로 올림 | `api.py` "잡티 제거 강화" 블록 | `=`, `i`의 점 등 작은 획이 통째로 삭제. 순서도의 `n = i` → `n  ı` |
| 2 | **`length_threshold=1.5`** — vtracer 유효 범위는 `[3.5, 10]` | `_vtrace_run.py` | 범위 밖 값이 경로를 과분할 → 형상 붕괴 |
| 3 | **언샤프 마스킹** (`addWeighted(1.5, -0.5)`) | `vector_autotune.preprocess_image` | 글자 테두리에 헤일로 → vtracer가 별도 색 레이어로 잡아 획이 이중으로 찍힘 |
| 4 | **2배 확대 후 곧바로 다시 축소** | `api.py` max_dim 처리 | 확대 이득은 없고 샤프닝 아티팩트만 남음 |

추가로 `hierarchical="cutout"` 고정(→ `stacked`가 품질 우위), `corner_threshold=10`(→ 곡선이 각짐).

2차 작업에서 추가로 발견한 것:
- **LANCZOS 확대가 링잉(오버슈트)** 을 일으켜 획 둘레에 후광을 만든다 → **BICUBIC**으로 교체.
  (테스트용2.png: SSIM 69.0 → 91.7, 474KB → 37KB)
- **모든 이미지에 확대가 이득인 게 아니다.** 글자가 많으면 이득, 큰 면으로 된 아이콘은 손해.
  → `small_mark_ratio`(작은 획 덩어리 비율)로 확대 배율을 자동 결정.
- **픽셀 단위 지표로는 사라진 글자를 못 잡는다.** `=` 하나가 없어져도 전체 잉크의 0.1%다.
  → 획 **덩어리(connected component)** 단위 F1로 교체. 옛 결과 재채점 시 25.2%로 정확히 찍혔다.

## 2. 완료된 작업

### 구조
```
src/vector/vector_autotune.py   분류 · 전처리 · 후보 파라미터 생성
src/vector/quality.py           결과 SVG 되-래스터화 후 채점 (SSIM + 획 보존 F1)
src/vector/svgmin.py            SVG 좌표 표기 무손실 축소
src/vector/_svg_raster.js       resvg-js 래스터라이저 (node)
app/ppt/_vtrace_run.py          job.json 받아 후보 트레이스·채점·최적안 채택 (별도 프로세스)
app/api.py::vectorize           오케스트레이션
```

- **분류 4종**: `lineart` / `diagram` / `logo` / `photo`. 샘플 6종 전부 정확히 분류.
- **유형별 전처리**
  - lineart: 흰 배경 합성 → 그레이 → 2배 확대 → Otsu 이진화 → `colormode=binary`
  - diagram/logo: 알파 보존 RGBA, **BICUBIC** 확대, 색 보존, `filter_speckle=2`
  - photo: 등배(≤1400px), 색 제한 없음, `filter_speckle=4`, `color_precision=8`
- **확대 배율 자동 판단**(`default_upscale`): `small_mark_ratio ≥ 0.5`면 2배, 아니면 등배.
- **`clamp_params()`**: 모든 vtracer 인자를 공식 유효 범위로 강제. 원인 #2 재발 차단.
- **진짜 채점**(`quality.py`): 결과 SVG를 resvg로 다시 PNG로 렌더해 원본과 비교.
  - `ssim` — 전체 구조 유사도
  - `ink_f1` — **획 덩어리 단위** 보존율(팽창 1px 허용). 선/글자가 핵심인 유형에서만 UI 노출.
  - node/resvg 없으면 `None` → UI에 점수 미표시(**가짜 숫자 금지**)
- **정밀 자동 튜닝**(체크박스, 기본 OFF): 후보 3~4개 실행 후 최고 점수 채택.
  점수 동률(±0.003)이면 파일이 작은 쪽.
- **SVG 무손실 축소**(`svgmin.py`): `1.0`→`1`, `0.6`→`.6`, `1 -2`→`1-2`. 약 7% 감소.
  래스터 해시가 원본과 **바이트 단위로 동일**함을 5개 파일에서 검증.
- **미리보기 복구**: 180KB 초과 SVG는 resvg로 PNG 렌더해 data URI로 표시.
- **배경 제거 defringe**: rembg의 반투명 경계는 피사체색+배경색이 섞여 있어 그대로 트레이스하면
  검은 윤곽선이 생긴다. 알파 이진화 + 1px 침식으로 제거 (SSIM 78.5 → 90.8, 1012KB → 780KB).
- **사진 경고**: 사진이고 결과가 원본의 2배를 넘으면 "원본을 그대로 쓰는 편이 낫다"고 UI에 명시.
- `requirements.txt`에 `opencv-python` / `numpy` / `scikit-image` 추가.

### 검증 방식
- 백엔드: `Api().vectorize()` 직접 호출로 6개 이미지 × (기본/autotune/custom/배경제거/오입력).
- 프런트엔드: `app/ui`를 복사해 `pywebview.api` 스텁을 붙이고 로컬 HTTP로 띄워 브라우저에서 검증.
  - 프리셋 6종 전환 시 수동 칸 활성/비활성 ✓
  - 결과 5종(큰SVG/작은SVG/점수없음/에러/취소) 렌더 ✓
  - 한글 변형 이름(`경량`) 표시 ✓ / 점수 없을 때 미표시 ✓
  - 변환 중 스피너·버튼 비활성·중지 버튼 노출 ✓, 취소 후 복귀 ✓

## 3. 남은 일

### (A) 실제 pywebview 앱에서 클릭 테스트 — **미완**
위 프런트엔드 검증은 **브라우저에서 스텁 API로** 한 것이다. 실제 `run_app.bat`으로 띄운
Edge WebView2 환경에서는 확인하지 않았다. 확인할 것:
- 파일 선택 다이얼로그 → 실제 경로로 변환
- **긴 변환(15초) 도중 '■ 중지'가 즉시 먹는지** (프로세스 kill 경로)
- data URI PNG 미리보기가 WebView2에서 렌더되는지 (CSP/용량 이슈 가능성)

### (B) photo 유형 — **1차 튜닝 완료, 추가 여지 있음**
52조합 격자 탐색(색 수 × filter_speckle × bilateral × 해상도)으로 프리셋 교체.
파인애플 기준 score 0.816 → 0.877, SSIM 87.1 → 92.2.
다만 **860KB로 원본(24KB)의 36배**다. 사진→SVG는 원리상 손해라는 걸 UI 경고로 알리는 선에서 멈췄다.
더 하려면: 영역 분할 후 평탄한 영역만 큰 패스로 묶기, 그라데이션 메시 추출 등. 투자 대비 효과는 낮아 보인다.

### (C) 컬러 도식 용량 — **부분 해결**
878KB → (무손실 축소) 819KB. 여전히 크다. 85%가 `<path d>` 좌표이고 경로가 2922개라
표기 최적화로는 한계다. 근본 감소는 **같은 색 인접 경로 병합**이 필요한데 기하 연산이라 별도 작업.
autotune의 `경량`(color_precision=6) 변형이 710KB까지 내려준다.

> 참고: autotune은 **품질 우선**이라 더 큰 파일을 고를 수 있다. 모델_도식에서 `고해상`(1317KB)이
> 획 보존 99.7%로 `경량`(710KB, 97.4%)을 이겼다. 의도된 동작이다 — '정밀' 모드니까.

### (D) 배경 제거 — **완료**
rembg 경로 실행 검증 + defringe 추가. 첫 실행은 모델 로드로 ~25초, 이후 ~10초.

### (E) PPT 파이프라인 연동 — **미착수**
발표자료 탭에서 이미지 삽입 시 자동 벡터화하는 흐름은 없다. 필요한지 사용자 판단 필요.
(사진은 (B) 결론대로 벡터화가 손해라 로고·도식에만 적용하는 게 맞다.)

### (F) 참고 레포 재확인 — **미착수**
사용자가 준 두 레포(`olivierroy/vtracer_autotune`, `raphaelmansuy/vectalab`)는 직접 읽지 않았다.
현재 구현은 "실제 트레이스 → 되-래스터화 → 점수 비교"라는 autotune의 핵심 발상만 독립적으로 구현한 것.

## 4. 손대면 안 되는 것 (재발 방지)

1. `filter_speckle`을 이미지 특성으로 **자동 상향하지 말 것**. 작은 글자가 즉사한다.
2. `length_threshold`는 반드시 `[3.5, 10]`. `clamp_params()`를 우회하지 말 것.
3. 트레이스 전 **샤프닝(언샤프 마스킹) 금지**. 헤일로가 색 레이어로 잡힌다.
4. 확대 보간은 **BICUBIC**. LANCZOS는 오버슈트해서 획 둘레에 후광을 만든다.
5. 품질 지표는 **획 덩어리 단위**로. 픽셀 IoU/F1은 사라진 글자를 못 잡는다.
6. 채점 불가 시 **점수를 지어내지 말 것**. `None`을 그대로 흘려보내 UI에서 감춘다.
7. 입력은 RGBA로 다룰 것. RGB로 바꾸면 투명이 검정이 된다.
8. `svgmin`에서 **`.` 앞 공백은 지우지 말 것**. `1 .5` → `1.5`가 되어 좌표 하나가 사라진다
   (실제로 렌더가 달라졌던 버그. 지금은 `-` 앞에서만 지운다.)
