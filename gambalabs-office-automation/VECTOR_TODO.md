# 벡터 변환(비트맵→SVG) 재작업 — 진행 상황 및 남은 일

작업일: 2026-08-06 / 대상: `app/api.py::vectorize`, `src/vector/*`, `app/ppt/_vtrace_run.py`, `app/ui/*`

## 1. 무엇이 문제였나 (재현·확인 완료)

Gemini가 만들어 둔 `src/vector/vector_autotune.py`는 **docstring만 있고 실제 알고리즘은 없는 껍데기**였다.
"다중 파라미터 SSIM 평가 및 최적 SVG 생성"이라고 적혀 있었지만 후보 탐색 루프가 없었고,
`compute_ssim()`은 **무조건 `0.88`을 반환하는 상수 함수**였다(UI에 "SSIM 88%"로 표시되던 그 숫자).

글자가 깨진 실제 원인 4가지 — 모두 재현해서 확인했다.

| # | 원인 | 위치(옛 코드) | 결과 |
|---|---|---|---|
| 1 | **`filter_speckle` 강제 상향** — 전처리 후 색 수가 6000을 넘으면 무조건 `10`으로 올림 | `api.py` "잡티 제거 강화" 블록 | `=`, `i`의 점 등 작은 획이 통째로 삭제. 순서도의 `n = i` → `n  ı` |
| 2 | **`length_threshold=1.5`** — vtracer 유효 범위는 `[3.5, 10]` | `_vtrace_run.py` | 범위 밖 값이 경로를 과분할 → 형상 붕괴 |
| 3 | **언샤프 마스킹** (`addWeighted(1.5, -0.5)`) | `vector_autotune.preprocess_image` | 글자 테두리에 헤일로 → vtracer가 별도 색 레이어로 잡아 획이 이중으로 찍힘 |
| 4 | **2배 확대 후 곧바로 다시 축소** | `api.py` max_dim 처리 | 확대 이득은 없고 샤프닝 아티팩트만 남음 |

추가로 `hierarchical="cutout"` 고정(→ `stacked`가 품질 우위), `corner_threshold=10`(→ 곡선이 각짐).

측정값(모델_도식.png, 컬러 도식):

| | SSIM | 획 보존 | 용량 |
|---|---|---|---|
| 수정 전 | 92.5% | **25.2%** | 184KB |
| 수정 후 | 97.6% | **96.7%** | 878KB |

수정 전에는 `feature`/`release`/`hotfix`/`Check out` 등 **텍스트 라벨이 전부 소실**됐다.

## 2. 무엇을 했나 (완료)

### 새 구조
```
src/vector/vector_autotune.py   분류 · 전처리 · 후보 파라미터 생성
src/vector/quality.py           결과 SVG 되-래스터화 후 채점 (SSIM + 획 보존 F1)
src/vector/_svg_raster.js       resvg-js 래스터라이저 (node)
app/ppt/_vtrace_run.py          job.json 받아 후보 트레이스·채점·최적안 채택 (별도 프로세스)
app/api.py::vectorize           오케스트레이션
```

- **분류 4종**: `lineart`(흑백 선화·순서도·도면) / `diagram`(컬러 도식·차트·스크린샷) / `logo` / `photo`.
  채도·이진성·엣지 밀도·색 수로 판별. 샘플 6종 전부 정확히 분류됨.
- **유형별 전처리**
  - lineart: 흰 배경 합성 → 그레이 → 2배 확대 → Otsu 이진화 → `colormode=binary`
  - diagram/logo: 알파 보존 RGBA, **BICUBIC** 확대(LANCZOS는 링잉으로 후광 발생), 색 보존, `filter_speckle=2`
  - photo: bilateral 평활화 + 축소 + 32색
- **확대 배율 자동 판단**: `small_mark_ratio`(작은 획 덩어리 비율)로 글자 유무를 추정.
  글자가 많으면 2배 확대(획 복원 이득), 큰 면으로 된 아이콘이면 등배(확대해도 얻을 정보 없음 + 후광 손해).
- **`clamp_params()`**: 모든 vtracer 인자를 공식 유효 범위로 강제. 원인 #2 재발 차단.
- **진짜 채점**: 결과 SVG를 resvg로 다시 PNG로 렌더해 원본과 비교.
  - `ssim` — 전체 구조 유사도
  - `ink_f1` — **획 덩어리 단위** 보존율. 픽셀 IoU로 재면 `=` 하나가 사라져도 전체 잉크의 0.1%라 점수가 안 움직인다. 덩어리로 세면 "마크 하나가 통째로 사라짐"이 그대로 찍힌다.
  - node/resvg가 없으면 `None` 반환 → UI에 점수를 아예 표시하지 않음(**가짜 숫자 금지**)
- **정밀 자동 튜닝**(UI 체크박스, 기본 OFF): 후보 3~4개를 실제로 돌려 최고 점수 채택.
  품질이 사실상 동률(±0.003)이면 파일이 작은 쪽을 고름.
- **미리보기 복구**: SVG가 180KB를 넘으면 resvg로 PNG 렌더해 data URI로 표시(예전엔 "미리보기 생략" 문구만 떴다).
- UI: 프리셋 4종으로 재정리, 수동 칸은 '수동 직접 설정'일 때만 활성, 잘못된 팁 문구 교체.
- `requirements.txt`에 `opencv-python` / `numpy` / `scikit-image` 추가(원래 코드가 쓰면서 선언은 안 돼 있었음).

## 3. 남은 일

### (A) 실제 앱에서 클릭 테스트 — **미완, 우선순위 1**
지금까지 검증은 전부 Python에서 `Api().vectorize()`를 직접 호출한 것이다.
`run_app.bat`으로 앱을 띄워 **SVG 변환 탭을 손으로 눌러** 확인해야 할 것:
- 프리셋 드롭다운 변경 시 수동 칸이 비활성/활성 되는지
- '정밀 자동 튜닝' 체크 시 결과 줄에 채택된 변형 이름(예: `경량`, `직선`)이 한글로 제대로 뜨는지
- 큰 SVG일 때 PNG 미리보기가 실제로 보이는지
- '■ 중지' 버튼이 autotune 도중에도 즉시 먹는지 (후보 여러 개를 도는 중 kill)

### (B) `photo` 유형 품질 — **미착수**
파인애플.webp가 SSIM 87.1 / 획 보존 61.5로 유일하게 낮다.
사진은 원리상 벡터화가 손해라 "이 정도가 한계"일 수도 있지만, 아직 제대로 튜닝하지 않았다.
시도해볼 것: 색 수(16/32/64) × filter_speckle(8/12/16) × bilateral 강도 격자 탐색,
`layer_difference` 조정, 사진은 애초에 SVG를 권하지 않는 안내 문구.
(참고: `photo`의 채점 지표는 `color`(SSIM+색오차)이므로 위 표의 '획 보존' 숫자는 선택에 쓰이지 않는다.)

### (C) 컬러 도식 용량 — **부분 해결**
모델_도식이 878KB. autotune의 `경량`(color_precision=6) 변형이 이미 이걸 골라준 결과다.
더 줄이려면 SVG 후처리(중복 경로 병합, 좌표 정밀도 재조정, SVGO 상당) 검토.
PPT에 여러 장 넣으면 파일이 무거워질 수 있다.

### (D) 배경 제거(rembg) 경로 미검증
`remove_bg=True` 경로는 코드만 고쳤고 실행은 안 해봤다(rembg 모델 다운로드 필요).
배경 제거 후 이미지를 새 원본으로 취급해 재분류하도록 바꿨는데, 이게 의도대로 도는지 확인 필요.

### (E) PPT 파이프라인 연동
지금은 SVG 변환 탭에서 파일만 떨궈준다. 발표자료 탭에서 이미지 삽입 시 자동으로 벡터화해
넣는 흐름은 아직 없다. 필요한지 사용자 판단 필요.

### (F) 참고 레포 재확인
사용자가 준 두 레포(`olivierroy/vtracer_autotune`, `raphaelmansuy/vectalab`)는 **직접 읽지 않았다.**
현재 구현은 "실제 트레이스 → 되-래스터화 → 점수 비교"라는 autotune의 핵심 발상만 독립적으로 구현한 것이다.
두 레포에 더 나은 파라미터 격자나 지표가 있는지 확인하면 (B)/(C)에 도움이 될 수 있다.

## 4. 손대면 안 되는 것 (재발 방지)

1. `filter_speckle`을 이미지 특성으로 **자동 상향하지 말 것**. 작은 글자가 즉사한다.
2. `length_threshold`는 반드시 `[3.5, 10]`. `clamp_params()`를 우회하지 말 것.
3. 트레이스 전 **샤프닝(언샤프 마스킹) 금지**. 헤일로가 색 레이어로 잡힌다.
4. 확대 보간은 **BICUBIC**. LANCZOS는 오버슈트해서 획 둘레에 후광을 만든다.
5. 채점 불가 시 **점수를 지어내지 말 것**. `None`을 그대로 흘려보내 UI에서 감춘다.
6. 입력은 RGBA로 다룰 것. RGB로 바꾸면 투명이 검정이 된다(기존 버그 이력).
